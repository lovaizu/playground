# What the plan says

## What the work is for

The README greets new contributors and points them to the CONTRIBUTING file, so someone who comes to contribute knows where to start.

## The CONTRIBUTING file

This work makes a short CONTRIBUTING.md at the top of the repository, so the README's pointer leads to a file that is there; what it says is decided with the documents after the plan sign-off.

## What shows the work is done

The README has, right below its description, one line that greets new contributors, and its link opens CONTRIBUTING.md, so a new contributor meets the greeting within the first lines and reaches the file it points to.

## Documents

The plan lists the documents readme (README.md) and contributing (CONTRIBUTING.md) alone, in that order; the plan's own decisions are its record, not a document the purpose needs.

## No UX document

The work has no UX document, since a README line and a short CONTRIBUTING.md hold no flow of use for a reader to get through.

## Document readme

README.md is the document readme, of kind readme, so the greeting line is made and checked for the README's own readers.

## Document contributing

CONTRIBUTING.md is the document contributing, of kind contributing, made to the checklist .rn/checklists/contributing.md, which is made first, so the file is made and checked for someone coming to contribute rather than for a newcomer to a product.

## No architecture document

The work has no architecture document, since two documents and no code hold no parts for a later builder to see.
